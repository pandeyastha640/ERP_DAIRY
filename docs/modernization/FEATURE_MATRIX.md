# R0 Feature Matrix

Statuses describe current source evidence. **VERIFIED WORKING** is reserved for a repeatable test of the behavior named; source code or a visible button alone is insufficient. `test:phases` exercises selected API paths, not every page. Page behavior, responsive layout, assistive technology, and Hindi are otherwise **NOT VERIFIED**.

**Current role boundary:** `src/App.tsx` applies a UI module list for CEO, COO, Operations Manager, Admin, Plant Manager, Procurement Manager, Finance Manager, and Field Staff. R0 adds coarse server-side route policies for API roles. Those policies do not yet form a unified permission catalogue. Farmer is absent from the current UI role union and is denied business API routes until ownership-scoped access is implemented. UI gating is not security enforcement.

## Cross-module quality evidence

| Concern | R0 evidence |
| --- | --- |
| Loading/success/error | Some direct API pages have loading/error handling; context writes often show success before API resolution and only log failures. No standard async mutation state. |
| Validation | Validation is inconsistent across routes. Several accept defaults or trust client totals/status. Server-side role policy was added, but semantic input validation remains a release task. |
| Mobile | Field view is touch-oriented. Every module's responsive behavior has not been tested at agreed viewport sizes. |
| Accessibility | Shared controls exist, but there is no WCAG 2.2 AA audit or automated keyboard/screen-reader suite. NOT VERIFIED. |
| Hindi | No localization framework or language resources found. Hindi localization is NOT IMPLEMENTED; scattered text is hard-coded English. |
| Automated coverage | API phase smoke and R0 auth tests only. No repeatable tests for all 20 UI workflows. |
